# Bots 群聊 · dsh-bots

**简体中文** · [English](README.en.md)

> **把不同职责的 Bot 拉进同一个对话，让 Bots King 分派任务、汇总结果。**

`dsh-bots` 为 DeepSeek Harness 添加自定义 Bot 和群聊模式。你可以给成员命名、定义职责、指定模型与思考强度，在原生输入框中描述任务或 `@` 指定成员，并在同一条时间线上查看各 Bot 的署名回复。

**当前版本：`v0.1.0`** · **已验证桌面宿主：DeepSeek Harness `0.2.2-rc.1`** · 支持桌面端与 Web

## 这样用

<!-- 截图预留 1：群聊总览。展示署名时间线、底部成员栏和原生输入框。建议路径：assets/group-chat.png。 -->

1. **定义成员。** 点击侧栏工作区上方的 **Bots**，创建 Bot 并填写名称、职责。主 Bot **Bots King** 默认显示，自动加入每个群聊。
2. **新建群聊。** 新建会话并选择工作区，在输入框附近选择 **群聊**，勾选成员后点击 **确认成员**。选择 **默认** 则沿用 Harness 原生对话行为。
3. **发出任务。** 直接在原生输入框描述目标，让 Bots King 分派；也可以输入 `@成员名` 限定本轮参与的子 Bot。
4. **查看结果。** 时间线按顺序展示任务分派、成员署名回复和主 Bot 汇总。点击底部成员可插入 `@`；成员较多时可横向滚动。

| 想做什么 | 可以这样说 |
| --- | --- |
| 让主 Bot 安排分工 | “请为离线任务清单应用设计方案，安排成员分别给出实现建议和验收意见，最后汇总。” |
| 指定一个成员 | “@架构师 请给出模块划分和关键技术取舍。” |
| 指定多个成员 | “@架构师 @审阅员 请先提出方案，再检查遗漏和边界条件。” |
| 直接向主 Bot 提问 | “@Bots King 请总结目前的结论，不要派发新任务。” |
| 保存个人偏好 | “@Bots King 请记住：我希望先看结论，再看实施步骤。” |

示例中的成员需要先创建并加入当前群聊。不点名，或只点名 `@Bots King` 时，由主 Bot 决定是否派发及派给谁；点名子 Bot 时，本轮子任务限定在指定成员范围内。

群聊纵向占满可用对话区域，时间线和成员栏横向跟随输入框尺寸。只有时间线内部滚动；**编队、轨迹、上下文** 保留 Harness 原生视图。

## 安装

先在 Harness 的标准 API 配置中配置可用模型。插件直接使用宿主模型配置，无需另填 API Key。

### 桌面端

打开 **插件 → 添加插件**，将 **安装源** 选为 **npm 官方源**，把下面的 Git 地址粘贴到 **包名或地址**：

```text
git+https://github.com/lonelycrab888/dsh-bots.git#v0.1.0
```

安装后在插件页启用 **dsh-bots**。若侧栏没有出现 **Bots**，请先结束正在运行的任务，再完整退出并重新打开桌面端。

Git 地址用于获取插件，npm 源用于下载依赖。如果安装日志显示 GitHub 对某个 npm 依赖返回 404，请检查是否误将 GitHub 仓库地址填入了安装源。

### Web CLI

```sh
dsh plugin --profile web add 'git+https://github.com/lonelycrab888/dsh-bots.git#v0.1.0'
dsh web
```

本地仓库包含 `lib/` 构建产物，发布时请一并提交。桌面端与 Web 使用各自的 profile，Bot 定义、长期记忆和会话数据不会自动跨 profile 同步。

### 从源码打包

在仓库根目录执行：

```sh
npm ci
npm run typecheck
npm test
npm run build
npm pack
```

将生成的安装包添加到对应 profile：

```sh
# 桌面端（macOS 默认安装路径）
"/Applications/DeepSeek Harness.app/Contents/Resources/runtime/cli/bin/dsh" plugin --profile desktop add "$PWD/dsh-bots-0.1.0.tgz"

# Web 端
dsh plugin --profile web add "$PWD/dsh-bots-0.1.0.tgz"
```

## Bot 定义与模型配置

<!-- 截图预留 2：Bots 定义页。展示 Bots King、子 Bot 卡片、成员人数上限、模型及思考强度选项。建议路径：assets/bot-library.png。 -->

每个子 Bot 都有自己的名称和职责。卡片中的长描述可以独立滚动，底部的模型、思考强度和编辑按钮保持对齐。

| 设置 | 行为 |
| --- | --- |
| **名称与职责** | 名称必须唯一，最多 24 个字符，支持中英文、数字、下划线和连字符；职责最多 6000 个字符 |
| **每个群聊最多加入的子 Bot 数** | 可设为 1–12，初始默认 4；Bots King 自动加入，不占名额 |
| **使用模型** | 默认跟随当前对话；也可为 Bots King 或任一子 Bot 单独指定宿主已配置的模型 |
| **思考强度** | 指定模型后显示该模型提供的原生档位；选择“模型默认”使用模型默认值。跟随当前对话时同时继承其思考强度 |
| **停用与恢复** | 停用后不再出现在新群聊候选中；勾选“显示已停用 Bot”可以恢复 |

模型与思考强度选项来自宿主标准 API 配置。修改 API 配置后，可点击 **刷新配置** 更新列表；模型没有提供可选档位时，思考强度选择器会显示说明并禁用。切换模型会清除此前指定的强度，避免使用不兼容档位。

**名称、职责和成员上限用于新建群聊；模型与思考强度在下一次 Bot 执行时读取，对已有群聊也生效。** 已有群聊保存成员职责快照，编辑或停用定义不会改写历史成员及回复。定义库最多保存 100 个 Bot，含停用项。

## Bots King 如何分派任务

<!-- 截图预留 3：一次完整的派发过程。展示用户目标、Bots King 分派、子 Bot 回复和最终汇总。建议路径：assets/task-dispatch.png。 -->

Bots King 先理解目标，再根据当前群聊成员的职责制定任务计划。子 Bot **按顺序执行**，后面的成员可以参考前面成员的本轮结果，最后由 Bots King 汇总。每轮每名子 Bot 最多执行一项任务；简单问题也可以由主 Bot 直接回答。

插件会校验计划中的成员、任务数量及点名范围。无效计划会尝试修正一次，仍失败则显示错误；成员执行失败时保留错误信息，由主 Bot 在汇总中说明。

每轮通常包含一次规划、每个参与成员一次执行和一次汇总的模型请求，实际 token 用量随任务与成员数量变化。**定义 Bot、选择成员或修改设置本身不会调用模型。**

点击 Harness 原生停止按钮可取消当前轮次，尚未派发的任务不会继续执行。重启后恢复成员和历史，不会自动重跑中断的任务。

## 记忆如何保存

<!-- 截图预留 4：Bots King 长期记忆管理。展示记忆开关、自动更新开关、有效条目与已移出条目。建议路径：assets/king-memory.png。 -->

| 数据 | 保存范围 | 是否跨群聊 |
| --- | --- | --- |
| Bot 定义与模型选择 | 当前 profile 的插件配置 | 同一 profile 的群聊可复用定义 |
| 群聊历史与 Bot 子会话 | 各自所属的群聊 | 子 Bot 不会自动读取其他群聊历史 |
| Bots King 个人长期记忆 | 当前 profile 的插件配置 | 同一 profile 内的 Bots King 共享 |

Bots King 的长期记忆保存明确要求、稳定偏好和长期背景，**不是把所有历史群聊全文自动记住**。默认根据本轮用户消息提取记忆并保留原文依据，不会把子 Bot 输出自动当作用户事实。只有 Bots King 直接读取跨群聊记忆，也可以将与任务相关的信息用于派发。

在 **Bots → Bots King → 管理长期记忆** 中，可以查看、添加、编辑、移出和恢复条目，也可以关闭长期记忆或单独关闭自动更新。群聊中可直接说：

```text
@Bots King 请记住：回复方案时先给结论，再列实施步骤。
@Bots King 请忘记我之前关于回复格式的偏好。
```

有效记忆最多 **32 条**，每条最多 **600 个字符**；有效与已移出条目合计最多 128 条，每轮最多更新 3 条。容量满时会提示处理，不会静默淘汰旧条目。并发修改会检查配置版本，冲突时需刷新后重试。

移出记忆只停止后续跨群聊注入，不删除原聊天内容；原群聊仍可能从自身上下文获知该信息。关闭长期记忆会停止注入，已经保存的条目仍然保留。

## 当前范围

- **文本群聊与顺序派发。** 当前 Bot 禁用工具调用，不能通过本插件直接执行终端、修改文件或调用搜索工具；暂不支持并行派发、附件处理、Markdown 渲染、流式回复或工作流依赖图。
- **复用宿主 Agent 运行机制。** Bots King 和子 Bot 使用独立持久化 Agent 会话。采用宿主 Agent 机制不代表开放全部工具，也不会更改全局 Agent Loop 设置。
- **保留原生体验。** 使用原生输入框、停止控制与模型配置，保留编队等原生视图；无需依赖增强开关插件。
- **历史兼容。** 支持早期开发原型的双 Bot 群聊历史，旧群聊再次发送消息时自动添加 Bots King；`@主Bot` 仍兼容。

## 停用与卸载

桌面端可在 **插件** 页停用或卸载。Web CLI 使用：

```sh
dsh plugin --profile web remove dsh-bots
```

停用或卸载会清理 Bots 入口、群聊覆盖层、样式和监听，恢复原生对话布局。插件不会覆盖原生 API、模型或 Agent Loop 全局配置。

**Bot 定义、长期记忆和群聊历史会保留，重新安装后可恢复。** 这不会清除历史数据，也不会撤销你在使用期间主动修改的宿主设置。

## 开发与验证

`npm run typecheck` 检查类型，`npm test` 覆盖配置校验、成员选择、点名路由、派发计划、记忆、模型与强度保存以及启停生命周期，`npm run build` 生成发布产物。

`scripts/smoke.mjs` 提供隔离 Web 模型替身测试，需要 Chrome 与 Playwright CLI。当前版本已通过 21 项自动测试，并完成桌面端卡片、强度保存、原生编队恢复和停用/卸载验证。拖动输入框宽度后的同步仍需人工复核，尚未取得可靠的桌面自动化验收结果。
