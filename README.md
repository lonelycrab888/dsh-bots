# Bots 群聊 · roundtable-bots

**简体中文** · [English](README.en.md)

**每个 Bot 都有标准 Agent 独聊，共享群聊记忆，由 KingBot 组织协作。**

在 DeepSeek Harness 中与 KingBot 聊天、写作、分析、搜索和处理文件；需要协作时，让它创建 Bot、建立群聊并发送消息。群聊中，KingBot 按成员职责组织发言，结合已有结果继续讨论并汇总结论。

**宿主要求：** DeepSeek Harness `>=0.2.2-rc.1`（已测试 rc.1、rc.2） · 桌面端 / Web

[安装](#安装) · [长期记忆](#记忆如何保存)

## 功能概览

- **每个 Bot 都能原生独聊。** 主 Bot 和子 Bot 均使用 Harness 标准 Agent 会话，支持流式回复、工具、审批和上下文管理。KingBot 继续具备创建 Bot、建群、发消息与跟进群任务的完整能力。
- **专属工作区禁止手动新建。** KingBot 工作区的新会话按钮禁用；顶部新会话和快捷键也会在请求发出前拦截。请从 Roundtable 打开已有独聊，或切换到其他工作区新建普通对话与群聊。自动创建 Bot 独聊、清空页面及重置主 Bot 记忆继续可用。
- **工作区内置顶。** KingBot 独聊始终位于其工作区会话列表首位，新建或清空子 Bot 独聊、重启及调整排序后仍保持首位。
- **自动创建、唯一窗口。** 创建 Bot 时自动在 KingBot 工作区创建独聊，升级时为已有 Bot 补建。反复打开会复用同一窗口，清空页面后只有新的窗口可继续对话。
- **三层记忆。** 每个 Bot 的独聊长期记忆、所有群聊的共享记忆、当前窗口上下文共同工作。
- **群内思考过程。** 每条 Bot 发言可展开模型实际返回的思考内容，实时更新并随群聊保存；未返回思考内容的模型不会出现此区域。
- **群聊继续更顺畅。** “按你说的做”带上上次主持建议；“已核对，继续”优先处理当前议题。新的初稿要求和用户更正会保留到后续派发。
- **核对与讨论分开。** 有待核对操作时仍能读资料和撰写回复；新的修改操作在核对后恢复。修复核对时部分操作记录无法保存的问题。
- **故障反馈更准确。** 意图识别失败单独提示并保留进度。主 Bot 独聊移除了额外的“群聊回执与历史记录”面板。

- **重置记忆与清空页面。** 重置长期记忆时同步归档旧独聊、开启空白上下文；独聊中的“清空页面”只更新当前对话，长期记忆保留。
- **简单交流直接回复。** 群聊中的纯问候、感谢和在场确认由 KingBot 简短回应，不创建讨论任务；带具体要求或子 Bot 点名的消息继续正常处理。

## 这样用

1. **选择主 Bot 工作区。** 打开 **Roundtable**，用“选择文件夹”或绝对路径指定已有目录，点击“启用工作区”。启用时在工作区内的 `.dsh-bots` 保存记忆；后续文件操作遵循你的请求和宿主权限。
2. **定义成员。** 点击侧栏工作区上方的 **Roundtable**，创建 Bot 并填写名称、职责，也可以在专属对话中让 KingBot 创建。首次安装仅显示主 Bot **KingBot**，不预置任何子 Bot。所有子 Bot 都由你创建。创建后自动出现独聊，可点击“与该 Bot 对话”；KingBot 自动加入每个群聊。
3. **新建群聊。** 在主 Bot 专属工作区之外新建会话，在输入框附近选择 **群聊**，勾选成员后点击 **确认成员**。选择 **默认** 则沿用 Harness 原生对话行为。
4. **发出任务。** 直接描述目标，由 KingBot 主持讨论。只 `@` 一位子 Bot 时由它直接回复，点名多位时由 KingBot 在这些成员之间主持讨论。
5. **查看结果。** 群聊气泡展示主持提问、成员署名回复和主 Bot 汇总。在原生输入框输入 `@`，从「群聊成员」选择要点名的人。

| 想做什么 | 可以这样说 |
| --- | --- |
| 请 KingBot 主持讨论 | “请讨论离线任务清单应用的设计。比较各自的实现建议和风险，最后汇总结论。” |
| 指定一个成员 | “@架构师 请给出模块划分和关键技术取舍。” |
| 指定多个成员 | “@架构师 @审阅员 请讨论方案的遗漏和边界条件。” |
| 暂停群聊 | “先到这里，我想调整一下方向。” |
| 保存个人偏好 | 在 KingBot 专属对话中说“请记住我希望先看结论，再看实施步骤。” |

请先创建架构师、审阅员等示例成员并加入当前群聊。未点名子 Bot 时，KingBot 从群成员中选择发言者。

群聊纵向占满可用对话区域，时间线和议题摘要跟随输入框宽度。**编队、轨迹、上下文** 继续使用 Harness 原生视图。

## 安装

先在 Harness 的标准 API 配置中配置可用模型。插件使用宿主配置，无需单独填写 API Key。

### 安装本地发布包

需要本地安装包时，可从仓库的 Releases 下载 `roundtable-bots-x.x.x.tgz`。下文的 `x.x.x` 请替换为实际下载的版本号。在下载目录打开终端，先退出正在使用的 Harness，再选择对应命令：

```sh
# macOS 桌面端（默认应用路径）
"/Applications/DeepSeek Harness.app/Contents/Resources/runtime/cli/bin/dsh" plugin --profile desktop add "$PWD/roundtable-bots-x.x.x.tgz"

# Web 端
dsh plugin --profile web add "$PWD/roundtable-bots-x.x.x.tgz"
```

安装或升级后重新打开 Harness，在插件页启用 **roundtable-bots**。升级同名包会保留 Bot 定义、会话和工作区记忆。桌面端和 Web 使用各自的 profile，需分别安装。

### 桌面端

打开 **插件 → 添加插件**，将 **安装源** 选为 **npm 官方源**，把下面的 Git 地址粘贴到 **包名或地址**：

```text
git+https://github.com/lonelycrab888/roundtable-bots.git#main
```

`#main` 固定从主分支安装，该分支同时适配 `rc.1` 与 `rc.2`。需要按宿主版本自动选择最新兼容发行版时，使用下方插件索引。

**通过索引选择最新兼容发行版**

1. 在 **插件 → 已安装 → 实验性插件** 启用 **自定义插件索引**。
2. 打开 **发现**。已有索引时，在索引下拉菜单中选择 **管理索引源…**。首次配置时，点击 **添加索引源**。
3. 粘贴下面的 URL，点击 **添加**。关闭对话框后，在 **roundtable-bots** 索引中打开 **Bots 群聊** 查看推荐版本。

```text
https://raw.githubusercontent.com/lonelycrab888/roundtable-bots/main/market-index.json
```

安装后在插件页启用 **roundtable-bots**。若侧栏没有出现 **Roundtable**，请先结束正在运行的任务，再完整退出并重新打开桌面端。

Git 地址用于获取插件，npm 源用于下载依赖。如果安装日志显示 GitHub 对某个 npm 依赖返回 404，请检查是否误将 GitHub 仓库地址填入了安装源。

### Web CLI

```sh
dsh plugin --profile web add 'git+https://github.com/lonelycrab888/roundtable-bots.git#main'
dsh web
```

本地仓库包含 `lib/` 构建产物，发布时请一并提交。桌面端与 Web 使用各自的 profile，Bot 定义和会话数据不会自动跨 profile 同步；只有显式选择同一工作区时才访问同一份记忆数据库。

### 从旧包 dsh-bots 迁移

插件在已安装列表中显示为 `roundtable-bots`。从旧包 `dsh-bots` 升级时，请先退出宿主，在同一 profile 中切换包。

1. 备份该 profile 的 `cordis.patch.yml`。默认桌面 profile 的文件在 `~/.dsh/profiles/desktop/cordis.patch.yml`。
2. 用下文的 CLI 命令安装 `roundtable-bots`，然后运行 `dsh plugin --profile desktop remove dsh-bots`。桌面端使用下文所列的应用内 CLI 路径，Web 则将 profile 改为 `web`。
3. 在备份和当前配置中找到 `id: dsh-bots` 条目，将其 `name: dsh-bots` 改为 `name: roundtable-bots`，保留原 `id`、`config` 和其他字段。如果条目没有 `name`，保留现有配置即可。
4. 重开宿主。新包沿用同一工作区中的记忆库和同一 profile 中的聊天记录。

### 从源码打包

在仓库根目录执行：

```sh
npm ci
npm run typecheck
npm test
npm run build
package_file="$(npm pack --silent)"
```

在同一个终端中，将生成的安装包添加到对应 profile。使用已下载的发布包时，在文件所在目录执行 `package_file=roundtable-bots-x.x.x.tgz`，再运行对应的安装命令。

```sh
# 桌面端（macOS 默认安装路径）
"/Applications/DeepSeek Harness.app/Contents/Resources/runtime/cli/bin/dsh" plugin --profile desktop add "$PWD/$package_file"

# Web 端
dsh plugin --profile web add "$PWD/$package_file"
```

## 与 KingBot 单独对话

选择工作区后，点击 **与 KingBot 对话** 打开或继续唯一的专属会话。使用该会话自身的原生 Harness Agent，可自由聊天、写作、分析、搜索和处理文件。沿用原生流式回复、工具执行、审批、停止与上下文管理。回答直接使用自然语言，长度随任务需要调整。

额外提供创建 Bot、创建群聊及向群聊发送消息的工具。普通聊天按当前需求回答，管理操作以工具回执为准。独聊只展示原生会话界面。旧独聊记录和群聊回执仍保留，并按上下文预算供 KingBot 查询和使用。

可以说：“帮我创建两个子 Bot，一个负责技术架构，一个负责质量验收，名称和能力描述由你拟定。”主 Bot 将生成名称和职责，经宿主校验后保存到定义库，结果会在时间线确认。创建后的成员由你在新群聊中选择，不自动加入已有群聊。

**专属工作区只允许与 KingBot 对话。** 不能在其中新建普通对话或群聊；此前已有的群聊可查看历史，但不能继续运行。请在其他工作区创建群聊。

首次配置会将旧版已保存记忆迁移一次。更换主 Bot 工作区会使用新目录的独立记忆库，原目录数据保留，不会自动合并。无论群聊位于哪个工作区，主 Bot 都使用当前选定的专属工作区记忆库。

### 清空独聊页面

在 KingBot 独聊输入框上方点击 **清空页面 → 确认清空页面**，会归档当前独聊并打开新的空白独聊。新会话不继承旧消息、工具结果或群聊回执，继续使用原工作区、Agent 预设和所选模型。已保存的长期记忆、Bot 定义及群聊保留。旧对话可从宿主归档记录中回查，不能继续作为当前 KingBot 独聊执行。

要同时清除长期记忆，请在 **Roundtable → 重置 Bots 数据** 中选择 **主 Bot 记忆**。重置完成后会自动打开新的 KingBot 独聊，避免旧消息让主 Bot 看起来仍“记得”。执行中的任务需先停止。

## Bot 定义与模型配置

「Roundtable」显示头像目录，点击头像或名称进入设置。KingBot 单独占首行，子 Bot 每行居中。头像为透明底，KingBot 在浅色主题使用深色鲸鱼，在深色主题使用白色鲸鱼，保留金色王冠。独聊和群聊都显示当前账户的用户头像。「显示已停用 Bot」和「重置 Bots 数据」位于目录底部。每个子 Bot 都有自己的名称和职责。

| 设置 | 行为 |
| --- | --- |
| **名称与职责** | 名称必须唯一，最多 24 个字符，支持中英文、数字、下划线和连字符；职责最多 6000 个字符 |
| **每个群聊最多加入的子 Bot 数** | 可设为 1–12，初始默认 4；KingBot 自动加入，不占名额 |
| **使用模型** | 默认跟随当前对话；也可为 KingBot 或任一子 Bot 单独指定宿主已配置的模型 |
| **思考强度** | 指定模型后显示该模型提供的原生档位；选择“模型默认”使用模型默认值。跟随当前对话时同时继承其思考强度 |
| **停用与恢复** | 停用后不再出现在新群聊候选中；勾选“显示已停用 Bot”可以恢复 |
| **删除** | 二次确认后移除定义，永久停用旧编号；重新创建同名 Bot 会生成新编号 |

模型与思考强度选项来自宿主标准 API 配置。修改 API 配置后，可点击 **刷新配置** 更新列表；模型没有提供可选档位时，思考强度选择器会显示说明并禁用。切换模型会清除此前指定的强度，避免使用不兼容档位。

**名称、职责和成员上限用于新建群聊；模型与思考强度在下一次 Bot 执行时读取，对已有群聊也生效。** 已有群聊保存成员职责快照，编辑或停用定义不会改写历史成员及回复。定义库最多新增至 20 个子 Bot，含停用项。

### 删除与重新创建

点击子 Bot 卡片上的 **删除**，阅读提示后点击 **确认删除**。KingBot 本身不能删除。

- 删除会撤销该 Bot 在所有群聊中的派发资格，并中止当前正在执行的群聊轮次。旧群聊保留历史回复，`@` 菜单会移除此成员。
- KingBot 下次执行时使用新的调度会话，不再注入删除前的群聊上下文；个人长期记忆中的旧编号会被替换为“∅”（已删除编号），其他个人偏好保留。
- 重新创建同名 Bot 会生成新的独立编号，需要新建群聊并重新勾选；它不会继承已删除 Bot 的会话或身份。
- 系统仅在内部保留不可复用的旧编号记录，用于拒绝旧编号，且不作为主 Bot 的记忆输入。历史日志保留，因此这里的“忘记”指不再用于模型上下文和调度，并非删除磁盘上的全部历史记录。

升级不会清空已有 Bot 定义或个人记忆。在已使用过的 profile 中重装后仍看到旧成员时，可在定义页手动删除；全新 profile 默认没有子 Bot，也没有预置长期记忆。

## KingBot 如何主持群聊

在群聊直接发送消息即可。KingBot 每次只选下一位发言者，根据已经出现的观点决定是继续追问、请另一位回应，还是收束。输入 `@架构师 @审阅员` 可以限定参与者。仅点名一位时，由这位成员直接回答。

支持用「可以，就按照你说的做」承接主持人的上一条建议。「已核对，继续」默认作用于当前议题，即使群内有多个旧议题。此前有操作结果待核对时仍可继续讨论、读取资料和撰写回复，新的修改操作在核对后恢复。意图识别调用失败会单独提示，并保留议题进度。

讨论中可输入新指令，并用 Harness 的「插话发送」。在默认排队设置下，按 `⌘ Enter`（macOS）或 `Ctrl Enter`（Windows/Linux）插话，普通回车排队。插话会停止当前生成，KingBot 随后根据新指令和已完成的发言继续。也可直接发「等一下，先别让成员继续发言」之类的消息，KingBot 会暂停并询问下一步。若同时明确说明新任务，会按新任务继续。

同一群聊可以直接发起新任务。要继续已有讨论，可以说「请继续分析上一轮的方案」。每位成员在一次讨论中最多发言两次。主持流程参考了 Grok Bot 的点名和可见交接。 [Grok Bot 群聊与协作说明](https://docs.x.ai/grok-bot/chat-and-collaboration)

### 运行与等待

**单次运行总时限默认关闭。** Bot 持续输出时不会因累计运行超过 120 秒而停止。用户插话或停止优先于当前执行，已发表内容和有效的部分输出保留；结果不明的工具操作须先核对，不会自动重放。

插件配置中的 `memberLimits` 使用毫秒：

| 配置 | 默认值 | 含义 |
| --- | --- | --- |
| `childTotal` | `0` | 关闭单次运行总时限 |
| `firstToken` | `120000` | 模型首包等待时间 |
| `modelQuiet` | `90000` | 生成中连续无有效进展的等待时间 |
| `hostQuiet` | `45000` | 显示仍在等待的提示，不取消或重复发起子任务 |

工具沿用自身的超时与权限设置；模型服务和 Harness 的限制仍由它们决定。真正停滞时，群里显示可继续的未完成状态。

### 文件、网络与 Skill

把文档拖到原生输入框，写下希望 Bot 核对的内容，再发送。用 `@成员名` 指定回答者。桌面端若只插入 `@/绝对路径` 或 `@"带空格的绝对路径"`，插件会保存对应文件的附件副本。支持文本、Word `.docx` 和带文字层的 PDF，每个文档最多 20 MB。每个导入失败的文件都会单独提示，其余附件仍可使用。明确追问同一议题时，可继续使用该议题的附件。扫描版 PDF 需要先做文字识别。

KingBot 专属独聊直接使用原生会话的 Agent 预设、工作目录、沙箱及审批策略。群聊中的 KingBot 和子 Bot 执行任务时继承所属会话的预设、工作目录和沙箱策略。可用工具由预设和宿主配置决定，包括 `@deepseek-ai/dsh-tool-fs` 提供的文件工具，以及可用的 `web_search`、`web_fetch`。网络搜索使用 Harness 配置的搜索服务和凭据。委派会话使用 Harness 的非交互审批策略，需要交互批准的操作会被拒绝。

Bot 可通过 `skill` 加载 `SKILL.md`，再用 `read` 读取引用文件。`@deepseek-ai/dsh-agent-instructions` 按宿主配置加载工作区的 `AGENTS.md` 等指令文件，默认上限为 65,536 字节。

## 请 KingBot 建群并跟进任务

在 KingBot 专属对话里，可以说「把刚才的离线清单方案交给群聊讨论，给我一个可执行的结论」。KingBot 根据当前对话选择成员和工作区，信息充分时通过工具创建群聊。有缺口时会询问需要补充的信息。你也可以明确指定成员或只要求建群。

已有群可以持续操作，不必重新建群。可以说「看看那个群的进度」「把这段补充给刚才的群」「让他们接着讨论」，也可指定群名。KingBot 每轮都能查找群、读取进度、原样发通知、更新要求或交办新任务。群名有歧义时会询问工作区；已经确认的目标会保存，重启后仍可续发。通知只增加一条 KingBot 发言；更新原议题时停止旧轮并保留上下文，新任务使用自己的目标。实际投递由宿主回执确认，结果回到发起请求的独聊。

存在待完善方案时，直接在独聊中补充工作区、调整成员，或要求确认、取消方案。

群建好后，可在 Harness 的工作区或会话搜索中打开它。有任务时，KingBot 会在新群主持讨论，并将结果关联到发起请求的独聊；你可以继续询问进度和结论。只建群时，成员就位后等待消息。

## 记忆如何保存

每个 Bot 在新对话中使用三层记忆：

| 记忆层 | 保存位置 | 使用方式 |
| --- | --- | --- |
| 自己的独聊长期记忆 | KingBot 工作区的 `.dsh-bots/king-memory.sqlite`；子 Bot 各有 `bot-<标识>-memory.sqlite` | 每个 Bot 读取自己的偏好与长期背景，跨窗口保留 |
| 所有群聊的共享记忆 | 各群聊所属工作区的 `.dsh-bots/group-memory.sqlite` | KingBot 和所有子 Bot 均可检索已登记工作区中的群聊记录，结果带工作区、群聊和消息来源 |
| 当前窗口上下文 | Harness 原生会话日志 | 当前窗口的消息、附件和工具结果由标准 Agent 管理 |

独聊长期记忆保存明确要求、稳定偏好和长期背景，保存动作需要本轮用户原文依据。每个 Bot 分库存储，不会自动把自己的独聊内容写入共享群聊库。群聊中的 Bot 也可读取它自己的长期记忆。当前用户指令优先于历史记忆。

群聊公共消息会自动写入共享库；升级后会从旧群聊日志补建索引。全文保存在工作区中，模型按需检索相关片段；长消息可用 `messageId` 与 `nextOffset` 继续读取，更多记录可用 `nextPage` 翻页。定向私信、独聊内容和思考过程不进入公共记忆索引。未完成发言保留状态，不能当作已确认结论。群聊的任务进度和执行上下文仍独立，可以在多个群中同时工作。

在 **Roundtable → KingBot → 管理工作区记忆** 或 **Roundtable → 子 Bot → 管理独聊记忆** 中，可以搜索、添加、编辑、固定、移出、恢复和导出该 Bot 的长期记忆。长期记忆和自动保存开关对所有 Bot 生效，控制独聊长期记忆；公共群聊记录仍保留并可检索。开启后，可以在任一 Bot 的独聊中说：

```text
请记住：回复方案时先给结论，再列实施步骤。
请忘记我之前关于回复格式的偏好。
```

独聊记忆无固定总条数上限，单条最多 **600 字符**，每轮自动更新最多 3 条。SQLite/FTS5 使用关键词和中文二元词检索，不是向量语义搜索，也不会一次将全部历史塞入模型。详见 [记忆设计与参考项目](MEMORY-DESIGN.md)。

**清空页面**只归档当前窗口并创建空白上下文，独聊长期记忆和群聊共享记忆保留。每个 Bot 始终只有一个当前可用的独聊，旧窗口仅供回查。**重置主 Bot 记忆**清空 KingBot 的个人记忆并更换其窗口，保留子 Bot 记忆与共享群聊记录。移出记忆不会删除原聊天内容。

## 当前范围

- **群聊时间线。** 支持文档附件、Markdown 回复和可折叠的模型思考过程；正文在完成后显示。
- **群聊上下文。** 每轮讨论使用独立的 Bot 执行会话。追问时从当前群聊历史中取用相关发言。
- **保留原生体验。** 使用原生输入框、停止控制与模型配置，保留编队等原生视图；无需依赖增强开关插件。
- **历史兼容。** 支持早期开发原型的双 Bot 群聊历史，旧群聊再次发送消息时自动添加 KingBot；`@主Bot` 仍兼容。

## 停用与卸载

桌面端可在 **插件** 页停用或卸载。Web CLI 使用：

```sh
dsh plugin --profile web remove roundtable-bots
```

停用或卸载会清理 Bots 入口、群聊覆盖层、样式和监听，恢复原生对话布局。插件不会覆盖原生 API、模型或 Agent Loop 全局配置。专属 Bots 工作区同时从侧栏移除，其可见会话暂时归档，避免出现在未分组列表；重新启用或重装后恢复工作区和原先可见的会话。原先已归档的会话保持归档。工作区文件、主 Bot 记忆与会话历史不会删除。

**Bot 定义、长期记忆和群聊历史会保留，重新安装后可恢复。** 这不会清除历史数据，也不会撤销你在使用期间主动修改的宿主设置。

## 重置 Bots 数据

打开 **Roundtable → KingBot → 重置 Bots 数据**，独立勾选需要清空的项目，再输入 `RESET` 并确认。默认不勾选任何项目；运行中的 Bot 任务须先停止。

| 项目 | 重置结果 |
| --- | --- |
| **Bots 成员** | 删除全部子 Bot（含已停用成员），保留主 Bot、主 Bot 模型及人数上限。旧编号保持不可复用，同名成员重建后使用新编号 |
| **主 Bot 记忆** | 清空当前所选工作区的有效、已移出和固定记忆、检索索引及旧审计内容，同时清空旧版迁移记忆；归档旧独聊并建立空白上下文，保留记忆开关。必须先选择工作区 |
| **旧会话关联** | 解除专属工作区与主 Bot 会话绑定，原专属会话归档、旧群聊改为只读。重新选择工作区后创建新的主 Bot 专属会话 |

只处理勾选的项目。仅解除会话关联不会清空记忆；重新选择原目录后仍可访问原记忆。重置会更新 Bot 执行上下文，不再注入重置前的历史。重置中断时保留待完成记录，重启后继续；未完成前暂停 Bot 执行，也可在重置面板重试。

**重置不能在插件中撤销，但不删除原聊天日志、已导出的文件或其他工作区的记忆文件。** 全部勾选适合重新开始使用；彻底删除磁盘历史仍需在宿主中单独处理。若已手动删除工作区目录，插件启动后会解除失效关联，保留成员定义，让你重新选择已有目录；不会擅自创建目录。

## 开发与验证

`npm run typecheck` 检查类型，`npm test` 覆盖配置校验、成员选择、点名路由、派发计划、记忆、模型与强度保存以及启停生命周期，`npm run build` 生成发布产物。

自动测试覆盖超过 32 条记忆的持久化与检索、数据库重开、版本冲突、成员创建与编号退役、专属工作区限制，以及关闭后的工作区恢复。

`npm run smoke`（别名 `npm run smoke:native`）使用 Chrome、Playwright CLI 和隔离的 Web profile，验证原生独聊、文件读取、搜索、创建 Bot、建群、发消息及重启后的记忆，也覆盖多个旧议题下的继续讨论、待核对操作、意图识别失败、清空页面、记忆重置后的上下文隔离及群聊问候。另验证 KingBot 工作区手动新建拦截、子 Bot 独聊自动创建与唯一性、独聊记忆隔离、跨群检索和思考记录重启恢复。模型使用确定性替身，验证执行链路，不代表真实模型的回答质量。

已通过类型检查、91 项自动测试及上述集成验收。重置功能另有使用合成数据的隔离 profile 界面验收。
