# Bots 群聊 · dsh-bots

**简体中文** · [English](README.en.md)

> **把不同职责的 Bot 拉进同一个对话，让 KingBot 分派任务、汇总结果。**

`dsh-bots` 为 DeepSeek Harness 添加自定义 Bot 和群聊模式。你可以给成员命名、定义职责、指定模型与思考强度，在原生输入框中描述任务或 `@` 指定成员，并在同一条时间线上查看各 Bot 的署名回复。

**当前版本 `v0.3.0`** · **适用宿主 DeepSeek Harness `0.2.2-rc.1` 与 `0.2.2-rc.2`** · 支持桌面端与 Web

## v0.3.0 新增

- **群聊讨论**。点「发起讨论」或用「讨论：」开头，成员先分别作答，再互评一轮，最后由 KingBot 汇总共识和分歧。
- **兼容 rc.1 与 rc.2**。同一个安装包使用对应宿主提供的运行时依赖。旧版 `v0.2.1` 只允许 `rc.1`，升级到 `rc.2` 时请用新版替换原安装。
- **点名识别**。修复中文冒号后紧接 `@` 时漏掉成员的问题。
- **主 Bot 改名为 KingBot**。原有可用的对话继续使用原会话、成员和上下文。

## v0.2.1 新增

- **选择性重置**：独立重置 Bots 成员、主 Bot 记忆和旧会话关联，输入 `RESET` 后确认。
- **重置后重新开始**：旧编号不可复用，旧执行上下文不再带入；支持重置中断后的恢复。
- **目录异常恢复**：工作区被删除时仍可进入 Bots 页面重新配置，移动目录时不再错误恢复旧路径会话。

## v0.2.0 新增

- **KingBot 专属对话**：选择独立工作区，使用原生输入框与主 Bot 单独交流。
- **由主 Bot 创建成员**：明确提出创建需求后，由 KingBot 拟定名称与能力描述，保存到 Bot 定义库。
- **跨工作区长期记忆**：其他工作区的群聊与主 Bot 专属对话共享记忆，不再按群聊数或固定条数限制容量。
- **工作区随插件启停**：关闭或卸载时隐藏 Bots 工作区；重新启用或安装时恢复，保留记忆和历史。

## 这样用

<!-- 截图预留 1：群聊总览。展示署名时间线、底部成员栏和原生输入框。建议路径：assets/group-chat.png。 -->

1. **选择主 Bot 工作区。** 打开 **Bots**，用“选择文件夹”或绝对路径指定已有目录，点击“启用工作区”。工作区内的 `.dsh-bots` 保存记忆，其他文件不被修改。
2. **定义成员。** 点击侧栏工作区上方的 **Bots**，创建 Bot 并填写名称、职责，也可以在专属对话中让 KingBot 创建。首次安装仅显示主 Bot **KingBot**，不预置任何子 Bot。所有子 Bot 都由你创建，KingBot 自动加入每个群聊。
3. **新建群聊。** 在主 Bot 专属工作区之外新建会话，在输入框附近选择 **群聊**，勾选成员后点击 **确认成员**。选择 **默认** 则沿用 Harness 原生对话行为。
4. **发出任务。** 直接在原生输入框描述目标，让 KingBot 分派；也可以输入 `@成员名` 限定本轮参与的子 Bot。
5. **查看结果。** 时间线按顺序展示任务分派、成员署名回复和主 Bot 汇总。点击底部成员可插入 `@`；成员较多时可横向滚动。

| 想做什么 | 可以这样说 |
| --- | --- |
| 让主 Bot 安排分工 | “请为离线任务清单应用设计方案，安排成员分别给出实现建议和验收意见，最后汇总。” |
| 指定一个成员 | “@架构师 请给出模块划分和关键技术取舍。” |
| 指定多个成员 | “@架构师 @审阅员 请先提出方案，再检查遗漏和边界条件。” |
| 直接向主 Bot 提问 | “@KingBot 请总结目前的结论，不要派发新任务。” |
| 保存个人偏好 | “@KingBot 请记住：我希望先看结论，再看实施步骤。” |

架构师、审阅员等仅是示例，不会随插件安装。示例中的成员需要先创建并加入当前群聊。不点名，或只点名 `@KingBot` 时，由主 Bot 决定是否派发及派给谁；点名子 Bot 时，本轮子任务限定在指定成员范围内。

群聊纵向占满可用对话区域，时间线和成员栏横向跟随输入框尺寸。只有时间线内部滚动；**编队、轨迹、上下文** 保留 Harness 原生视图。

## 安装

先在 Harness 的标准 API 配置中配置可用模型。插件直接使用宿主模型配置，无需另填 API Key。

升级已有安装时，先退出宿主，在同一 profile 执行 `add`，然后重新打开。已有 Bot 配置、记忆库和聊天历史沿用原存储。

### 桌面端

打开 **插件 → 添加插件**，将 **安装源** 选为 **npm 官方源**，把下面的 Git 地址粘贴到 **包名或地址**：

```text
git+https://github.com/lonelycrab888/dsh-bots.git#main
```

`#main` 固定安装分支上的版本。该分支发布的同一个包同时适配 `rc.1` 与 `rc.2`。要由宿主从发行版本中选出最新兼容版本，启用「实验性插件 → 自定义插件索引」，再到「发现 → 添加索引源」填入 [dsh-bots 插件索引](https://raw.githubusercontent.com/lonelycrab888/dsh-bots/main/market-index.json)。

安装后在插件页启用 **dsh-bots**。若侧栏没有出现 **Bots**，请先结束正在运行的任务，再完整退出并重新打开桌面端。

Git 地址用于获取插件，npm 源用于下载依赖。如果安装日志显示 GitHub 对某个 npm 依赖返回 404，请检查是否误将 GitHub 仓库地址填入了安装源。

### Web CLI

```sh
dsh plugin --profile web add 'git+https://github.com/lonelycrab888/dsh-bots.git#main'
dsh web
```

本地仓库包含 `lib/` 构建产物，发布时请一并提交。桌面端与 Web 使用各自的 profile，Bot 定义和会话数据不会自动跨 profile 同步；只有显式选择同一工作区时才访问同一份记忆数据库。

### 从源码打包

在仓库根目录执行：

```sh
npm ci
npm run typecheck
npm test
npm run build
npm pack
```

将生成的安装包添加到对应 profile：

```sh
# 桌面端（macOS 默认安装路径）
"/Applications/DeepSeek Harness.app/Contents/Resources/runtime/cli/bin/dsh" plugin --profile desktop add "$PWD/dsh-bots-0.3.0.tgz"

# Web 端
dsh plugin --profile web add "$PWD/dsh-bots-0.3.0.tgz"
```

## 与 KingBot 单独对话

选择工作区后，点击 **与 KingBot 对话** 打开或继续唯一的专属会话。它使用原生输入框和停止按钮，不需要先创建子 Bot。

可以说：“帮我创建两个子 Bot，一个负责技术架构，一个负责质量验收，名称和能力描述由你拟定。”主 Bot 将生成名称和职责，经宿主校验后保存到定义库，结果会在时间线确认。创建后的成员由你在新群聊中选择，不自动加入已有群聊。

<!-- 截图预留 5：主 Bot 专属对话，展示创建子 Bot 的请求与确认结果。建议路径：assets/king-chat.png。 -->

**专属工作区只允许与 KingBot 对话。** 不能在其中新建普通对话或群聊；此前已有的群聊可查看历史，但不能继续运行。请在其他工作区创建群聊。

首次配置会将旧版已保存记忆迁移一次。更换主 Bot 工作区会使用新目录的独立记忆库，原目录数据保留，不会自动合并。无论群聊位于哪个工作区，主 Bot 都使用当前选定的专属工作区记忆库。

## Bot 定义与模型配置

<!-- 截图预留 2：Bots 定义页。展示 KingBot、子 Bot 卡片、成员人数上限、模型及思考强度选项。建议路径：assets/bot-library.png。 -->

每个子 Bot 都有自己的名称和职责。卡片中的长描述可以独立滚动，底部的模型、思考强度和编辑按钮保持对齐。

| 设置 | 行为 |
| --- | --- |
| **名称与职责** | 名称必须唯一，最多 24 个字符，支持中英文、数字、下划线和连字符；职责最多 6000 个字符 |
| **每个群聊最多加入的子 Bot 数** | 可设为 1–12，初始默认 4；KingBot 自动加入，不占名额 |
| **使用模型** | 默认跟随当前对话；也可为 KingBot 或任一子 Bot 单独指定宿主已配置的模型 |
| **思考强度** | 指定模型后显示该模型提供的原生档位；选择“模型默认”使用模型默认值。跟随当前对话时同时继承其思考强度 |
| **停用与恢复** | 停用后不再出现在新群聊候选中；勾选“显示已停用 Bot”可以恢复 |
| **删除** | 二次确认后移除定义，永久停用旧编号；重新创建同名 Bot 会生成新编号 |

模型与思考强度选项来自宿主标准 API 配置。修改 API 配置后，可点击 **刷新配置** 更新列表；模型没有提供可选档位时，思考强度选择器会显示说明并禁用。切换模型会清除此前指定的强度，避免使用不兼容档位。

**名称、职责和成员上限用于新建群聊；模型与思考强度在下一次 Bot 执行时读取，对已有群聊也生效。** 已有群聊保存成员职责快照，编辑或停用定义不会改写历史成员及回复。定义库最多保存 100 个 Bot，含停用项。

### 删除与重新创建

点击子 Bot 卡片上的 **删除**，阅读提示后点击 **确认删除**。KingBot 本身不能删除。

- 删除会撤销该 Bot 在所有群聊中的派发资格，并中止当前正在执行的群聊轮次；旧群聊保留历史回复，但成员栏不再提供该 Bot 的点名入口。
- KingBot 下次执行时使用新的调度会话，不再注入删除前的群聊上下文；个人长期记忆中的旧编号会被替换为“∅”（已删除编号），其他个人偏好保留。
- 重新创建同名 Bot 会生成新的独立编号，需要新建群聊并重新勾选；它不会继承已删除 Bot 的会话或身份。
- 系统仅在内部保留不可复用的旧编号记录，用于拒绝旧编号，且不作为主 Bot 的记忆输入。历史日志保留，因此这里的“忘记”指不再用于模型上下文和调度，并非删除磁盘上的全部历史记录。

升级不会清空已有 Bot 定义或个人记忆。在已使用过的 profile 中重装后仍看到旧成员时，可在定义页手动删除；全新 profile 默认没有子 Bot，也没有预置长期记忆。

## KingBot 如何分派任务

<!-- 截图预留 3：一次完整的派发过程。展示用户目标、KingBot 分派、子 Bot 回复和最终汇总。建议路径：assets/task-dispatch.png。 -->

KingBot 先理解目标，再根据当前群聊成员的职责制定任务计划。子 Bot **按顺序执行**，后面的成员可以参考前面成员的本轮结果，最后由 KingBot 汇总。每轮每名子 Bot 最多执行一项任务；简单问题也可以由主 Bot 直接回答。

插件会校验计划中的成员、任务数量及点名范围。无效计划会尝试修正一次，仍失败则显示错误；成员执行失败时保留错误信息，由主 Bot 在汇总中说明。

每轮通常包含一次规划、每个参与成员一次执行和一次汇总的模型请求，实际 token 用量随任务与成员数量变化。**手动定义 Bot、选择成员或修改设置不会调用模型；让 KingBot 在对话中创建成员会调用模型。**

点击 Harness 原生停止按钮可取消当前轮次，尚未派发的任务不会继续执行。重启后恢复成员和历史，不会自动重跑中断的任务。

## 让成员讨论

群聊至少加入两名子 Bot，点击「发起讨论」或在消息开头输入 `讨论：`。也可以用英文前缀 `Discuss:`。

```text
讨论：@架构师 @审阅员 各自提出离线任务清单的存储方案，再点评对方的取舍。
```

点名时至少选两位；未点名时由 KingBot 选择至少两位。初答完成后，每位成功回复的成员看到本轮初答和已有互评，可针对其他成员的具体观点给出理由或修正。互评会在同一时间线标为「讨论」，每位成员最多增加一次回复。成功初答不足两位时，KingBot 汇总已有结果。这个流程借鉴了 Grok Bot 的明确点名和可见交接。 [Grok Bot 群聊与协作说明](https://docs.x.ai/grok-bot/chat-and-collaboration)

## 记忆如何保存

<!-- 截图预留 4：KingBot 长期记忆管理。展示记忆开关、自动更新开关、有效条目与已移出条目。建议路径：assets/king-memory.png。 -->

| 数据 | 保存范围 | 是否跨群聊 |
| --- | --- | --- |
| Bot 定义与模型选择 | 当前 profile 的插件配置 | 同一 profile 的群聊可复用定义 |
| 群聊历史与 Bot 子会话 | 各自所属的群聊 | 子 Bot 不会自动读取其他群聊历史 |
| KingBot 个人长期记忆 | 所选主 Bot 工作区的 SQLite 数据库 | 主 Bot 专属对话与其他工作区的群聊共享 |

KingBot 的长期记忆保存明确要求、稳定偏好和长期背景，**不是把所有历史群聊全文自动记住**。长期记忆与自动更新开启时，根据本轮用户消息提取记忆并保留原文依据，不会把子 Bot 输出自动当作用户事实。只有 KingBot 直接读取跨群聊记忆，也可以将与任务相关的信息用于派发。

在 **Bots → KingBot → 管理工作区记忆** 中，可以搜索、分页查看、添加、编辑、固定、移出、恢复及导出条目，也可以关闭长期记忆或单独关闭自动更新。群聊中可直接说：

```text
@KingBot 请记住：回复方案时先给结论，再列实施步骤。
@KingBot 请忘记我之前关于回复格式的偏好。
```

记忆总量不再设固定条数上限，也不受群聊数量限制；单条最多 **600 个字符**，每轮自动更新最多 3 条。使用本地 SQLite/FTS5 保存与检索，每次只把固定、相关和近期条目注入模型，避免记忆越多、上下文越大。检索使用关键词与中文二元词，不是向量语义搜索。详见 [记忆设计与参考项目](MEMORY-DESIGN.md)。

移出记忆只停止后续跨群聊注入，不删除原聊天内容；原群聊仍可能从自身上下文获知该信息。关闭长期记忆会停止注入，已经保存的条目仍然保留。

## 当前范围

- **文本群聊与顺序派发。** 当前 Bot 禁用工具调用，不能通过本插件直接执行终端、修改文件或调用搜索工具；暂不支持并行派发、附件处理、Markdown 渲染、流式回复或工作流依赖图。
- **复用宿主 Agent 运行机制。** KingBot 和子 Bot 使用独立持久化 Agent 会话。采用宿主 Agent 机制不代表开放全部工具，也不会更改全局 Agent Loop 设置。
- **保留原生体验。** 使用原生输入框、停止控制与模型配置，保留编队等原生视图；无需依赖增强开关插件。
- **历史兼容。** 支持早期开发原型的双 Bot 群聊历史，旧群聊再次发送消息时自动添加 KingBot；`@主Bot` 仍兼容。

## 停用与卸载

桌面端可在 **插件** 页停用或卸载。Web CLI 使用：

```sh
dsh plugin --profile web remove dsh-bots
```

停用或卸载会清理 Bots 入口、群聊覆盖层、样式和监听，恢复原生对话布局。插件不会覆盖原生 API、模型或 Agent Loop 全局配置。专属 Bots 工作区同时从侧栏移除，其可见会话暂时归档，避免出现在未分组列表；重新启用或重装后恢复工作区和原先可见的会话。原先已归档的会话保持归档。工作区文件、主 Bot 记忆与会话历史不会删除。

**Bot 定义、长期记忆和群聊历史会保留，重新安装后可恢复。** 这不会清除历史数据，也不会撤销你在使用期间主动修改的宿主设置。

## 重置 Bots 数据

打开 **Bots → KingBot → 重置 Bots 数据**，独立勾选需要清空的项目，再输入 `RESET` 并确认。默认不勾选任何项目；运行中的 Bot 任务须先停止。

| 项目 | 重置结果 |
| --- | --- |
| **Bots 成员** | 删除全部子 Bot（含已停用成员），保留主 Bot、主 Bot 模型及人数上限。旧编号保持不可复用，同名成员重建后使用新编号 |
| **主 Bot 记忆** | 清空当前所选工作区的有效、已移出和固定记忆、检索索引及旧审计内容，同时清空旧版迁移记忆；保留记忆开关。必须先选择工作区 |
| **旧会话关联** | 解除专属工作区与主 Bot 会话绑定，原专属会话归档、旧群聊改为只读。重新选择工作区后创建新的主 Bot 专属会话 |

只处理勾选的项目。仅解除会话关联不会清空记忆；重新选择原目录后仍可访问原记忆。重置会更新 Bot 执行上下文，不再注入重置前的历史。重置中断时保留待完成记录，重启后继续；未完成前暂停 Bot 执行，也可在重置面板重试。

**重置不能在插件中撤销，但不删除原聊天日志、已导出的文件或其他工作区的记忆文件。** 全部勾选适合重新开始使用；彻底删除磁盘历史仍需在宿主中单独处理。若已手动删除工作区目录，插件启动后会解除失效关联，保留成员定义，让你重新选择已有目录；不会擅自创建目录。

## 开发与验证

`npm run typecheck` 检查类型，`npm test` 覆盖配置校验、成员选择、点名路由、派发计划、记忆、模型与强度保存以及启停生命周期，`npm run build` 生成发布产物。

自动测试覆盖超过 32 条记忆的持久化与检索、数据库重开、版本冲突、成员创建与编号退役、专属工作区限制，以及关闭后的工作区恢复。

`npm run smoke` 使用 Chrome、Playwright CLI 和本地模型替身，在独立 Web profile 验证安装、主 Bot 工作区、点名派发、讨论互评、重启恢复和原生普通会话。
